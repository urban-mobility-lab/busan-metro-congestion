# 검증 시나리오: 대표 질문별 기대 호출과 답변

## 기준 상황

- 오늘은 2026-11-30(월) 19시(KST)다. "내일"은 2026-12-01(화)이다.
- API는 테스트 샘플 저장소 `data/samples/predictions/predictions_sample.parquet`를 쓴다.
  - `model-info`: `available_from=2026-12-01`, `available_to=2026-12-05`, `model_version=0.1.0-set1-sample`
  - 예측이 있는 역: 서면 1호선(119), 해운대(203), 연산 3호선(305), 미남 4호선(401)
  - 예측이 있는 날짜: 2026-12-01, 2026-12-05 (기간 안의 12-02~12-04는 없음)
- 아래 수치는 이 샘플로 API를 실제 호출해 확인한 값이다. 운영 저장소에서는 값이 다르므로 **호출 형태와 답변 구조**를 기준으로 확인한다.

## 체크리스트

각 시나리오에서 확인한다.

- [ ] 호출한 경로·파라미터가 "API 호출"과 같다(호출하지 않아야 하면 호출하지 않았다).
- [ ] 답변 수치가 응답 값과 같다(반올림만 허용, 추정·보간 없음).
- [ ] 해석 가정(출근 시간 범위, 별칭, 환승역 처리, `hour=24`)을 한 줄로 밝혔다.
- [ ] 실패·범위 밖이면 수치 없이 안내했다.

## 실패 경로

| # | 상황 | API 응답 | 기대 답변 |
| --- | --- | --- | --- |
| 20 | 서버가 꺼져 있음 | 연결 실패 → 1회 재시도 → 실패 | "예측 서버에 연결하지 못해 답할 수 없다". 수치·추정 없음 |
| 21 | 저장소가 비어 있음 | `503 PREDICTION_NOT_READY` | 예측이 아직 준비되지 않았다고 알린다. 재시도하지 않음 |
| 22 | 없는 역 번호로 호출됨 | `404 STATION_NOT_FOUND` | 역을 찾지 못했다고 알리고 역 목록으로 이름을 다시 확인 |
| 23 | `hour=0`으로 호출됨 | `422 INVALID_HOUR` | 요청을 고쳐 다시 호출하거나 시간대 범위(1~24)를 설명 |
| 24 | `date` 없이 호출됨 | `422 INVALID_REQUEST` | 날짜를 채워 한 번 다시 호출. 또 실패하면 실패를 알린다 |
