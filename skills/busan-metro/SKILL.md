# 부산 도시철도 혼잡도 예측 조회

부산 도시철도 1~4호선 역의 **시간당 승차+하차 합계 예측 인원**을 사전 예측 결과 조회 API(`docs/API_SPEC.md`)로 받아 한국어로 답한다. 대표 질문별 기대 호출과 답변은 [references/scenarios.md](references/scenarios.md)에 있다.

## 0. 꼭 지킬 원칙

1. **답변의 모든 수치는 이번 대화에서 받은 API 응답에서만 가져온다.** 기억, 상식, 다른 역·날짜 값으로 추정하거나 보간하지 않는다.
2. **API 호출이 실패하면 수치를 말하지 않는다.** 실패 사실과 응답의 `message`를 전하고 할 수 있는 다음 행동을 안내한다.
3. 값은 **역 전체의 승차+하차 합계 예측**이다. "혼잡률 %", "열차가 꽉 찬다", "승강장이 붐빈다"로 바꿔 말하지 않는다. "이용객이 많다/적다", "몇 명이 타고 내린다"로 표현한다.
4. API는 **과거 평소 값을 주지 않는다.** "평소보다 많다/적다"는 말하지 않는다. 비교는 응답으로 받은 시간대·역·날짜끼리만 한다.
5. 해석에 가정이 들어가면(예: "출근 시간 = 07~09시", "환승역 두 호선 합산") 답변에 그 가정을 한 줄로 적는다.

## 1. API

기본 주소는 환경 변수 `BUSAN_METRO_API_BASE`이고, 없으면 `http://localhost:8000`을 쓴다. 서버 실행은 `uv run uvicorn busan_metro_congestion.api.app:app`이다. 모든 응답은 JSON이고 날짜·시각은 한국 시간(KST)이다. `GET` 요청만 쓴다.

| 경로 | 입력 | 응답 |
| --- | --- | --- |
| `GET /api/v1/health` | 없음 | `{"status": "ok"}`. 서버 생존만 확인한다 |
| `GET /api/v1/model-info` | 없음 | `model_version`, `generated_at`, 예측 가능 기간 `available_from`~`available_to`, `station_count`, `row_count` |
| `GET /api/v1/stations` | `line_num`(1~4) 선택 | 역 목록. 역마다 `station_id`, `station_name`, `line_num`, `lat`, `lng` |
| `GET /api/v1/predictions` | `station_id`, `date`(YYYY-MM-DD) 필수, `hour`(1~24) 선택·반복 가능 | 역 정보(`station_id`, `station_name`, `line_num`, `lat`, `lng`), `date`, `model_version`, `generated_at`, `predictions[]` |

`predictions[]`의 항목은 `hour`, `target_datetime`, `predicted_passengers`(소수 첫째 자리 실수)다. `hour`를 생략하면 1~24 전체를 받는다. 중복 `hour`는 서버가 제거하고 오름차순으로 돌려준다.

호출 예:

```bash
curl -s "$BUSAN_METRO_API_BASE/api/v1/model-info"
curl -s "$BUSAN_METRO_API_BASE/api/v1/stations?line_num=2"
curl -s -G "$BUSAN_METRO_API_BASE/api/v1/predictions" \
  --data-urlencode "station_id=119" --data-urlencode "date=2026-12-01" \
  --data-urlencode "hour=8" --data-urlencode "hour=24"
```

예측 응답 예:

```json
{
  "station_id": 119,
  "station_name": "서면",
  "line_num": 1,
  "lat": 35.158282,
  "lng": 129.059556,
  "date": "2026-12-01",
  "model_version": "0.1.0-set1-sample",
  "generated_at": "2026-11-25T19:00:00+09:00",
  "predictions": [
    {"hour": 8, "target_datetime": "2026-12-01T08:00:00+09:00", "predicted_passengers": 4195.6},
    {"hour": 24, "target_datetime": "2026-12-02T00:00:00+09:00", "predicted_passengers": 168.0}
  ]
}
```

### 오류 응답

오류 본문은 항상 `{"code": "...", "message": "..."}`이다. `message`는 사용자에게 그대로 보여 줄 수 있는 한국어 문장이다. **상태 코드보다 `code`를 먼저 본다.**

| 상태 | code | 뜻 | 처리 |
| --- | --- | --- | --- |
| 404 | `STATION_NOT_FOUND` | 역 마스터에 없는 `station_id` | 역을 찾지 못했다고 알리고 역 목록으로 이름을 다시 확인한다 |
| 404 / 405 / 422 | `INVALID_REQUEST` | 경로·메서드 오류, 필수 값 누락, 날짜 형식 오류 | 요청을 고쳐 한 번만 다시 호출한다. 또 실패하면 실패를 알린다 |
| 422 | `INVALID_HOUR` | `hour`가 1~24 밖 | 요청을 고쳐 다시 호출한다. 고칠 수 없으면 시간대 범위를 설명한다 |
| 422 | `INVALID_LINE` | `line_num`이 1~4 밖 | 1~4호선만 제공한다고 알린다 |
| 422 | `DATE_OUT_OF_RANGE` | 그 역·날짜의 예측이 저장소에 없음 | 아래 "기간 판단"대로 안내한다 |
| 503 | `PREDICTION_NOT_READY` | 저장소 부재·빈 저장소·스키마 위반, 일부 시간대 누락 | 예측이 아직 준비되지 않았다고 알린다. 다시 시도하지 않는다 |

**기간 판단.** `DATE_OUT_OF_RANGE`는 "그 역·날짜의 행이 없다"는 뜻이다. 날짜가 `available_from`~`available_to` 안인데도 이 오류가 나면 기간 밖이 아니라 **그 역(또는 그 날짜)의 예측이 저장소에 없는 것**이다. 이때 `message`의 "기간을 벗어났습니다" 문장을 그대로 옮기지 말고 "○○역 ○월 ○일 예측은 아직 없습니다"라고 말한다. 기간 안의 모든 날짜가 있다는 보장은 없다.

### 데이터 의미

- `predicted_passengers`: 그 역의 한 시간 승차+하차 **예측** 인원. 답변에서는 정수로 반올림하고 "약"을 붙인다(4195.6 → 약 4,196명).
- `hour=h`는 `date`의 h시~h+1시다. `hour=8`은 08~09시다. **`hour=24`는 `date` 다음 날 00~01시**이며 `target_datetime`도 다음 날 00:00이다. `date`의 00~01시는 전날 `date`의 `hour=24`다.
- `hour` 1~4(01~05시)는 열차 운행이 없는 시간이라 값이 아주 작다. 이 시간은 비교·추천 대상에서 뺀다.
- 예측은 배치 추론이 미리 만들어 둔 값이다. 생성 시각은 `generated_at`이다.
- 제공하지 않는 정보: 과거 평소 값, 방향(상행/하행)별 수치, 승차·하차 분리, 혼잡률(%), 열차·칸·승강장 단위 값, 실시간 값, 1~4호선 밖 노선(동해선, 부산김해경전철 등).

## 2. 처리 순서

1. **기준 시각 확인.** 현재 날짜·시각(KST)을 시스템 정보에서 얻는다. 알 수 없으면 사용자에게 날짜를 묻는다.
2. **`GET /api/v1/model-info`** 로 `available_from`, `available_to`를 얻는다. 연결에 실패하면 `GET /api/v1/health`로 서버가 켜져 있는지 확인하고, 꺼져 있으면 6장의 연결 실패로 처리한다. `PREDICTION_NOT_READY`면 예측이 준비되지 않았다고 알리고 멈춘다.
3. **`GET /api/v1/stations`** 로 역 목록을 얻는다. 같은 대화에서 이미 받았으면 재사용한다. 특정 호선 역만 필요하면 `line_num`을 넘긴다.
4. 질문에서 **역 → station_id**(3장), **시간 표현 → date·hour**(4장)를 해석한다. 후보가 여러 개라 정할 수 없으면 호출 전에 되묻는다.
5. 날짜가 `available_from`~`available_to` 밖이면 `predictions`를 호출하지 않고 기간을 안내한다.
6. **`GET /api/v1/predictions`** 를 역마다 호출한다. 시간대가 정해져 있으면 `hour`를 넘기고, 비교·추천이면 생략해 24시간 전체를 받는다.
7. 질문 유형(5장)에 맞게 응답 수치만으로 답한다(7장 형식).

## 3. 역 이름 해석

`stations` 응답의 `station_name`과 대조해 `station_id`로 바꾼다. 아래 순서로 처음 결과가 나오는 단계에서 멈춘다.

1. **정확히 일치**: 입력 그대로 `station_name`과 같은 역. (`부산역`은 역 이름 자체가 "부산역"이다.)
2. **접미어 제거 후 일치**: 끝의 `역`, 공백, `(1호선)`·`1호선` 같은 호선 표기를 떼고 비교한다. `서면역` → `서면`, `연산역 3호선` → `연산` + 3호선.
3. **별칭표**(아래)로 바꾼 뒤 일치.
4. **부분 일치**: 입력이 들어간 `station_name`을 모은다.
   - 1개면 그 역을 쓰고 "○○역으로 보고 조회했다"고 밝힌다.
   - 여러 개면 **조회하지 말고** 후보를 나열해 되묻는다.
5. 그래도 없으면 **없는 역**으로 처리한다(6장).

### 환승역

서면, 연산, 덕천, 수영, 미남, 동래는 호선마다 `station_id`가 따로 있다.

| 역 | 호선별 station_id |
| --- | --- |
| 서면 | 1호선 119, 2호선 219 |
| 연산 | 1호선 123, 3호선 305 |
| 덕천 | 2호선 233, 3호선 313 |
| 수영 | 2호선 208, 3호선 301 |
| 미남 | 3호선 309, 4호선 401 |
| 동래 | 1호선 125, 4호선 402 |

번호는 역 목록 응답으로 다시 확인한다(위 표는 `data/reference/station_master.parquet` 기준 확인용이다).

- 호선을 말했으면 그 호선 ID 하나만 조회한다.
- 호선을 말하지 않았으면 **두 ID를 모두 조회**하고 호선별 값을 나란히 보여 준다. 합계를 말할 때는 "1호선 값 + 2호선 값을 더한 값"이라고 명시한다.
- 한 호선만 `DATE_OUT_OF_RANGE`이면 성공한 호선 값만 보여 주고 다른 호선은 예측이 없다고 밝힌다. 합계는 말하지 않는다.

## 4. 시간 표현 해석

기준은 한국 시간(KST) 현재 날짜다.

| 표현 | date | hour |
| --- | --- | --- |
| 오늘 / 내일 / 모레 | 오늘 / +1일 / +2일 | 질문에 따라 |
| 이번 주 금요일, 12월 5일 | 해당 날짜 | 질문에 따라 |
| 출근 시간, 아침 러시아워 | 해당 날짜 | 7, 8 (07~09시) |
| 퇴근 시간, 저녁 러시아워 | 해당 날짜 | 18, 19 (18~20시) |
| 점심 | 해당 날짜 | 12 (12~13시) |
| 오전 / 오후 / 저녁 / 밤 | 해당 날짜 | 6–11 / 12–17 / 18–20 / 21–24 |
| 8시, 아침 8시 | 해당 날짜 | 8 (08~09시) |
| 저녁 8시 | 해당 날짜 | 20 (20~21시) |
| 오전·오후 없이 "6시" 등 1~11시 | 해당 날짜 | 7~11은 오전으로 본다. 5~6은 새벽(첫차 무렵)·오후 모두 가능하므로 되묻거나 두 시간을 함께 보여 준다. 1~4는 운행이 없는 시간이므로 오후(13~16시)로 보고, 해석을 밝힌다 |
| ○일 밤 자정 직후, ○일 밤 12시 넘어서, 막차 무렵 | ○일 | 24 (○일 다음 날 00~01시) |
| ○일 새벽 0시~1시 | ○일 **전날** | 24 |

- 출근·퇴근·오전 등 범위 해석은 기본값이다. 답변에 "출근 시간은 07~09시로 보고 조회했다"처럼 적는다.
- "자정 직후"는 어느 날의 자정인지 모호하면 "내일 00~01시(= 오늘 `date`의 `hour=24`)"처럼 해석을 밝힌다. 이 경우 `date`가 바뀌어 예측 가능 기간 판단이 달라질 수 있다.
- 시간대를 말할 때는 항상 "08~09시"처럼 범위로 쓰고, `hour=24`는 "다음 날 00~01시"로 쓴다.

## 5. 질문 유형별 처리

### 5.1 단건 조회 — "내일 서면역 8시에 몇 명?"

1. 역·날짜·hour 해석 → `predictions?station_id=…&date=…&hour=8`.
2. 답: 예측 인원. 평소 값은 제공되지 않으므로 평소와 비교하지 않는다.
3. 환승역이면 호선별로 나눠 보여 준다.

### 5.2 시간대 비교 — "내일 서면역 출근 시간이랑 퇴근 시간 중 언제가 더 붐벼?"

1. 비교할 hour들을 모두 넣어 한 번에 호출한다(`hour=7&hour=8&hour=18&hour=19`).
2. 구간별 합계 또는 시간대별 값을 나란히 보여 주고, 더 많은 쪽을 말한다.
3. 구간 합계를 썼으면 "07~09시 두 시간 합계"처럼 단위를 밝힌다.

### 5.3 역 비교 — "내일 오후 6시 해운대역이랑 연산역 중 어디가 더 붐벼?"

1. 역마다 같은 `date`, 같은 `hour`로 호출한다. 환승역이 섞이면 호선별로 조회한다.
2. 표로 나란히 보여 주고 차이(명)를 말한다.
3. 한 역이라도 호출이 실패하면 성공한 역 값만 보여 주고 "○○역은 조회에 실패해 비교할 수 없다"고 말한다. 실패한 역 값을 추정하지 않는다.

### 5.4 한산한 시간 추천 — "내일 해운대역 언제 가면 한산해?"

1. `hour` 없이 24시간 전체를 호출한다.
2. 후보: 사용자가 범위를 말했으면 그 범위, 아니면 **06~22시(hour 6~21)**. 기본 범위를 썼으면 "06~22시 중에서 골랐다"고 밝힌다.
3. 후보 중 `predicted_passengers`가 가장 낮은 시간 1~3개를 값과 함께 추천하고, 가장 붐비는 시간도 참고로 덧붙인다.
4. "한산하다"는 이용 인원이 적다는 뜻일 뿐 열차 좌석 여유를 보장하지 않는다고 한 줄 덧붙인다.

### 5.5 날짜 비교 — "서면역 화요일이랑 토요일 중 언제 사람이 더 많아?"

1. 두 날짜가 모두 예측 가능 기간 안인지 확인한 뒤 날짜마다 같은 역·같은 hour로 호출한다(하루 전체면 hour 생략).
2. 하루 합계는 hour 5~24 값을 더해 구하고, "05시~다음 날 01시 합계"라고 밝힌다.
3. 한 날짜가 없으면(`DATE_OUT_OF_RANGE`) 비교할 수 없다고 알리고 있는 날짜 값만 보여 준다.

## 6. 실패와 범위 밖 질문

| 상황 | 처리 |
| --- | --- |
| 날짜가 `available_from`~`available_to` 밖 | 호출하지 않고 "조회 가능한 기간은 ○~○"을 알린다. 수치 없음 |
| 기간 안인데 `DATE_OUT_OF_RANGE` | "○○역 ○월 ○일 예측은 아직 없다"고 알리고 기간 안의 다른 날짜를 물어볼 수 있다고 안내 |
| `PREDICTION_NOT_READY` | 예측이 아직 준비되지 않았다고 알리고 나중에 다시 물어보라고 안내. 재시도하지 않음 |
| 없는 역(3장 5단계 또는 `STATION_NOT_FOUND`) | 1~4호선 역이 아니거나 이름을 찾지 못했다고 알리고 비슷한 이름 후보가 있으면 제시 |
| 5호선 등 1~4호선 밖 노선(`INVALID_LINE`) | 1~4호선만 제공한다고 알린다 |
| 평소 대비·방향별·승차/하차 분리·혼잡률(%)·칸별·실시간 질문 | 제공하지 않는 정보라고 먼저 밝히고, 제공하는 값(시간당 승하차 합계 예측)으로 대신 답할지 제안하거나 함께 보여 준다. 합계를 반으로 나누는 식의 추정은 하지 않는다 |
| 네트워크 오류, 타임아웃, `code`가 없는 5xx, JSON이 아닌 응답 | 한 번 다시 시도한다. 또 실패하면 "예측 서버에 연결하지 못해 답할 수 없다"고 알린다. 수치를 말하지 않는다 |
| `INVALID_REQUEST`, `INVALID_HOUR` | 요청을 고칠 수 있으면 고쳐 한 번 다시 호출하고, 아니면 실패를 알린다 |

## 7. 답변 형식

- 첫 줄에 결론("내일(12/1 화) 서면역 1호선 08~09시 예측은 약 4,196명입니다").
- 이어서 근거 수치. 여러 값은 표로.
- 마지막에 가정과 출처 한 줄: "출근 시간은 07~09시로 보았습니다 · 모델 ○○, 생성 ○○".
- 숫자는 천 단위 쉼표, 단위 "명". 응답 값을 반올림해 "약"을 붙일 수는 있지만 새 값을 만들지 않는다. 합계·차이는 응답 값으로 계산한 뒤 반올림한다.
